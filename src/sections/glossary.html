Glossary

Words this page uses that you may not have met in Python notebooks, in alphabetical order. A dotted underline in the text marks the first time a ticket uses one of them: select it and the definition opens next to the word. Each entry ends with a link to where the page teaches it. Punctuation is in the symbol lookup.

address

A byte's position in memory, written as a number. A reference or pointer holds one. On a 64-bit machine an address takes 8 bytes, which is why usize is 8 bytes there.

Where it's taught: week zero, memory

allocate

To get a block of memory to hold data while the program runs, usually from the heap. Giving it back is called freeing it. In Rust you rarely do either by hand: a Vec or String allocates as it grows, and its memory is freed when it's dropped.

Where it's taught: week zero, memory

associated function

A function in an impl block. Strictly, methods are associated functions too, but the name usually means one that takes no self: it belongs to the type, not to one value, and you call it on the type with ::, as in Bin::new(...) or Book::headers(). Python's nearest is a @staticmethod.

Where it's taught: ticket 6, a trait is a promise

big-O

A way of saying how a cost grows as the input grows, ignoring constant factors. O(1) stays flat, O(n) grows in step with the input, and O(n2) grows with its square: four times the data, sixteen times the work.

Where it's taught: ticket 3, big-O

binary

The file the compiler writes, also called an executable: machine code your processor runs directly. cargo build puts it under target/debug/. It runs without Rust installed, and it doesn't change until you build again.

Where it's taught: week zero, what cargo run does

borrow

To use a value through a reference without taking ownership of it: &x to read it, &mut x to change it. At any moment a value can have any number of & borrows or exactly one &mut, never both, and no borrow may outlive the value. A borrow lasts until its last use, which can be a later trip around a loop, not to the end of the block.

Where it's taught: ticket 1, borrowing

Box

Box<T> is a pointer to a T stored on the heap. The box owns the value, and when the box is dropped, so is the value, and its memory is freed. Box<dyn Error> uses one to hold an error of any type behind a pointer of one fixed size.

Where it's taught: ticket 6, trait objects

byte

Eight bits, each 0 or 1, which gives 256 patterns. Memory is counted in bytes: a u8 is one byte, an i64 is eight, and text is stored as bytes in UTF-8.

Where it's taught: week zero, bits, bytes and integers

cargo

Rust's build tool and package manager. It downloads the crates listed in Cargo.toml, calls the compiler, and runs your program, tests, formatter and linter: cargo build, cargo run, cargo test, cargo clippy.

Where it's taught: set up, the loop you'll run

clippy

Rust's linter, run with cargo clippy. It flags code that compiles but could be clearer, faster or more likely to be correct, the way ruff or pylint does for Python. Its warnings don't stop the build, and the house rules ask for none before a review.

Where it's taught: set up, the loop you'll run

clone

An explicit copy, made by calling .clone() on a type that implements Clone. For a String or a Vec it copies the contents on the heap too, so it can cost real time. Copy types are copied without being asked. Other types can be copied only with .clone(), and only if they implement Clone; a few, such as &mut references, don't.

Where it's taught: ticket 3, what each derive buys you

closure

A function with no name, written where it's used as |args| body. Python's lambda is the same idea, except a closure can be as long as you like. A closure can use variables from the code around it, which is called capturing; a fn can't.

Where it's taught: week zero, closures

commit

A snapshot git saves of the changes you staged with git add, with a message saying what changed and why. You can always get back to it.

Where it's taught: set up, the first commit

compile

To turn source code into machine code before the program runs. Rust's compiler, rustc, reads the whole program first and checks types, names and borrows, so many mistakes are errors you fix before anything runs. Python finds most of them only when it reaches the line.

Where it's taught: week zero, what cargo run does

Copy

A trait for types whose values can be copied by copying their bytes: integers, floats, bool, char, shared references such as &str, and arrays and tuples made only of these. Assigning or passing one hands over a copy and leaves the original usable. String and Vec aren't Copy, because they own memory on the heap, so they move instead.

Where it's taught: week zero, references

crate

One unit of compiled Rust, a library or a program, which the compiler builds as one piece. A package is what cargo downloads and builds, and it holds one or more crates. Day to day, people say crate for both, as in "the csv crate".

Where it's taught: set up, the SQLite crate

derive

#[derive(...)] above a struct or enum asks the compiler to write a trait's standard code for you: Debug for {:?}, Clone, PartialEq for ==, Ord for sorting, and so on. For the standard library's traits it only compiles when every field has the trait too. Crates can add derives of their own, such as clap's Parser.

Where it's taught: ticket 3, what each derive buys you

drop

To end a value's life and free what it owns. Rust drops a value when the variable that owns it goes out of scope, usually at a closing brace, and drop(x) does it early. A value that was moved is dropped by its new owner instead.

Where it's taught: week zero, memory

enum

A type whose value is exactly one of a fixed list of variants, such as Lost, Overdue { days } or Returned. Unlike a Python Enum, each variant can carry its own data, and a match on an enum must cover every variant. Option and Result are enums.

Where it's taught: ticket 3, enums

exit status

The number a process hands back when it ends, also called its exit code: 0 for success, anything else for failure. A panic in main exits with 101, and clap exits with 2 when a command is used wrongly. The shell keeps the last one in $?, and schedulers judge a run by it alone.

Where it's taught: week zero, your program is a process

expression

Code that produces a value, such as a + b, an if/else or a match. A statement does something and ends in ;. A block's value is its last expression when no semicolon follows it, which is how a Rust function usually returns.

Where it's taught: week zero, the shape of a program

floating point

How computers store numbers with fractions: in base 2, with a fixed number of significant bits, so most decimals, 0.1 among them, are stored very slightly off. f64 uses the same format as Python's float. Good for measurements and averages, wrong for money.

Where it's taught: ticket 3, how a computer stores 0.1

garbage collector

Part of a running program that finds values nothing refers to anymore and frees their memory. Python has one. Rust doesn't: ownership tells the compiler where each value can be freed, so it writes the freeing into the program.

Where it's taught: week zero, memory

generic

Written once for many types, with a type parameter such as the T in Vec<T> or fn print_table<T: TableRow>(rows: &[T]). Each place the code is used fills in a real type, and the compiler checks that use.

Where it's taught: ticket 6, one function, many types

hash table

A structure that finds a key without searching through every key: a hash function turns the key into a number, and the number picks the slot to look in. Two keys can land in the same slot, so the table has a plan for that too. On average, a lookup takes about the same time with ten keys or ten million. HashMap and HashSet are hash tables, as are Python's dict and set. Rust's keep no order.

Where it's taught: ticket 2, how a hash table finds things

heap

A large pool of memory that a running program can ask for blocks from, of any size, at any time. A Vec or String keeps its contents there, because they can grow. Rust gives a block back when the value that owns it is dropped.

Where it's taught: ticket 1, the stack and the heap

I/O

Input and output: reading and writing files, the terminal and the network. I/O can fail for reasons outside your program, such as a missing folder or a full disk, so I/O functions return a Result, often std::io::Result.

Where it's taught: ticket 1, write a file

impl

A block that holds the functions belonging to a type. impl Bin { ... } holds the type's own methods and associated functions. impl Display for Cents { ... } keeps a trait's promise for that type.

Where it's taught: week zero, structs and methods

infer

To work out a type from how a value is used, so you don't have to write it. Rust infers most variables' types, and your editor shows them in gray. Function signatures are always written out.

Where it's taught: week zero, variables

integration test

A test in a file in the tests/ folder. Cargo compiles each file as its own crate, which uses your library from outside and so can reach only pub items. That makes it the place to test a whole path through the code.

Where it's taught: ticket 5, integration tests

iterator

Something that hands out items one at a time, made with .iter(), .into_iter() or a range. Methods such as filter and map wrap it in another iterator, and nothing runs until something like count, sum or collect asks for the items. Python's iterators and generators are the same idea.

Where it's taught: week zero, tuples, arrays and vectors

library

A crate that other code uses, as opposed to a program you run. In a package it starts at src/lib.rs. A package can hold a library and a program together, and the program reaches the library by the package's name.

Where it's taught: ticket 5, modules

lifetime

The stretch of the program during which a reference is valid. When the compiler can't work out how references relate, you name a lifetime, such as 'a, to say what a result borrows from. Lifetimes exist only while compiling: they describe how long references stay valid, never change how long anything lives, and cost nothing when the program runs.

Where it's taught: ticket 3, lifetimes

macro

Code that writes code while compiling. Most are called with a !: println!, vec!, dbg!. A derive, such as #[derive(Debug)], is a macro too. Macros do what a function can't, such as take any number of arguments of any type, or check format text before the program runs.

Where it's taught: week zero, macros

match

Branching on the shape of a value. Each arm is a pattern, =>, and what to do. The compiler checks that the arms cover every possible value, so you can't forget None or a new enum variant, unless a catch-all _ arm swallows them for you.

Where it's taught: week zero, Option and Result

method

A function in an impl block whose first parameter is some form of self, called with a dot: bin.put_away(5). &self reads the value, &mut self may change it, and plain self takes it. Python's self is always the changing kind.

Where it's taught: week zero, structs and methods

module

A named section of code, declared with mod, whose items are private to it, and to the modules inside it, unless marked pub. In Python every file is a module. In Rust a file under main.rs or lib.rs is compiled only if a mod line names it.

Where it's taught: ticket 5, modules

monomorphization

How Rust compiles generic code: a separate copy of a generic function for each type it's called with, such as one print_table for Book and one for Loan. Each copy calls its type's methods directly, which is called static dispatch. The price is build time and program size.

Where it's taught: ticket 6, generics and trait objects, compiled

move

Handing ownership of a value to another variable or function. After a move the old name can't be used. A move copies only the value itself, not what it points to: for a Vec, its pointer, length and capacity, while the items on the heap stay where they are. Copy types are copied instead, and the original stays usable.

Where it's taught: ticket 1, borrowing

mutable

Allowed to change. A Rust variable can't change unless it's declared let mut, and a function changes a caller's value through a &mut reference. A Python variable can always be given a new value.

Where it's taught: week zero, variables

NaN

"Not a number", the float you get from things like 0.0 / 0.0. It isn't equal to anything, itself included. That's why f64 isn't Ord, so sort_by_key refuses it, and why it can't be a HashMap key. total_cmp gives floats a total order when you need one.

Where it's taught: ticket 2, sorting by a float

newtype

A struct with one unnamed field that wraps another type, such as struct Cents(i64). It costs nothing when the program runs, and it lets the compiler tell money apart from every other i64.

Where it's taught: ticket 3, money is not a float

Option

Option<T> is an enum that means maybe a T: either Some(value) or None. Rust uses it where Python would use None, and the type makes you handle the missing case before you can use the value.

Where it's taught: week zero, Option and Result

overflow

A result too big, or too small, for its fixed-size integer type, such as 250 + 10 in a u8. By default, plain +, - or * panics on it in a debug build and wraps around in a release build, and methods like checked_add let you choose. Parsing text into a number too big for its type returns an error instead. Python's integers grow instead, so they never overflow.

Where it's taught: week zero, bits, bytes and integers

ownership

Rust's rule that every value has exactly one owner, usually a variable. When the owner goes out of scope, the value is dropped. Ownership can be moved to a new owner, and the value can be lent out by borrowing. It's how Rust frees memory without a garbage collector.

Where it's taught: ticket 1, borrowing

panic

Rust stopping the program because something that should be impossible happened, such as reading past the end of a Vec or calling unwrap on an Err. It prints where and why, and in a program like yours, with one thread, it exits with status 101. A panic is for bugs. Bad input should be a Result.

Where it's taught: ticket 4, two kinds of failure

parse

To turn text into a typed value, such as "42" into a u32 or 10/15/2026 into a date, with an error when the text doesn't fit. A good parser returns a type that can only hold good values, so code further on doesn't have to check again.

Where it's taught: ticket 4, a parser

pointer

A value that holds the memory address of another value. A Rust reference is a pointer with rules: the compiler checks that it always points at a live value.

Where it's taught: week zero, memory

process

A running program. The operating system gives each one its own memory, the arguments it was started with, a working directory, and standard input, output and error. When it ends it hands back an exit status.

Where it's taught: week zero, your program is a process

refactor

To change the structure of code without changing what it does, such as splitting one long file into modules. A saved copy of the old output, and a diff against it after each step, shows that nothing moved.

Where it's taught: ticket 5, change the shape

reference

A pointer that lets code use a value without taking it. &x is a shared reference, for reading, and &mut x a mutable one, for changing. Making one is borrowing. The compiler checks that a reference never outlives the value it points at, and * follows it to the value.

Where it's taught: week zero, references

release build

A build made with --release: slower to compile, fully optimized, often many times faster than the default debug build, and, by default, without its overflow checks. It goes in target/release/. Time things only in release.

Where it's taught: week zero, what cargo run does

Result

Result<T, E> is an enum that means a T or an error of type E: Ok(value) or Err(error). Most functions that can fail return one, where Python would raise an exception, and ? hands an Err back to the caller.

Where it's taught: week zero, Option and Result

scope

The stretch of code where a name can be used. A variable's scope runs from its let to the end of its block, and when the owner of a value goes out of scope, the value is dropped. A trait or type is "in scope" in a file once a use line brings its name in.

Where it's taught: week zero, memory

signature

The part of a function before its body: the name, each parameter with its type, and after -> the type it returns. In Rust it also says whether the function borrows, changes or takes each argument, so you learn a lot before reading the body.

Where it's taught: week zero, the shape of a program

slice

A view of a run of items that sit side by side, written &v[1..3] or, as a type, &[T]. It borrows from a Vec or an array without copying. &str is the same idea for text.

Where it's taught: week zero, tuples, arrays and vectors

stable sort

A sort that keeps items with equal keys in the order they had before. sort, sort_by and sort_by_key are stable. The sort_unstable family may reorder equal items, and is often faster.

Where it's taught: ticket 1, sort

stack

The memory where each function call keeps its local variables. Room is made when a function is called and given back when it returns, which makes it fast, and everything kept there needs a size known when compiling. A Vec in a local variable keeps its pointer, length and capacity on the stack and its items on the heap.

Where it's taught: ticket 1, the stack and the heap

standard error

The output channel for messages about how a program is going: errors, warnings, dbg! output. eprintln! writes to it. Often shortened to stderr. Redirecting with > sends standard output to a file and leaves standard error on screen.

Where it's taught: ticket 6, processes, streams and exit codes

standard output

The output channel for a program's results, often shortened to stdout. println! writes to it. It and standard error both show in the terminal until one is redirected, as cargo run > out.txt does.

Where it's taught: ticket 6, processes, streams and exit codes

struct

A named group of fields, each with a type. Think of one row of a table with its column types written down, or a Python @dataclass whose types are checked when compiling.

Where it's taught: week zero, structs and methods

tag

A name git sticks on one commit, such as t1-submitted, so you and a reviewer can point at that exact version later. It stays on that commit when you make new ones.

Where it's taught: how reviews work, when to ask

trait

A named set of methods that a type can promise to have, such as Display, Ord or your own TableRow. A type keeps the promise in an impl Trait for Type block, and generic code can accept any type that has it. It's closer to a Python Protocol than to a class: a trait has no fields, and the compiler checks every use.

Where it's taught: ticket 6, a trait is a promise

trait bound

A requirement on a type parameter, as in <T: TableRow>: T can be any type that implements TableRow. Inside the function you can use only what the bound promises.

Where it's taught: ticket 6, one function, many types

trait object

dyn Trait: a value of some type that implements the trait, where the exact type is known only while the program runs. It always sits behind a pointer, such as &dyn Describe or Box<dyn Error>, which also points at a table of that type's methods. Each call is looked up there at run time, which is called dynamic dispatch.

Where it's taught: ticket 6, trait objects

unit test

A small test of one piece of code: a #[test] function inside a #[cfg(test)] module in the same file. cargo test runs them all. Unit tests can reach private functions, which integration tests can't.

Where it's taught: ticket 4, unit tests

UTF-8

The standard way to store text as bytes. Unicode gives every symbol a number, its code point, and UTF-8 stores each code point in one byte if it's ASCII and two to four bytes otherwise. What you'd call one character is usually one code point, but not always: an accent can be a code point of its own. Rust text is always UTF-8, so .len() on a String counts bytes, not characters.

Where it's taught: week zero, text is bytes

variant

One of the forms an enum's value can take, such as Some and None for Option, or Ok and Err for Result. A variant can carry data of its own, like Overdue { days }.

Where it's taught: ticket 3, enums

vector

Vec<T>, Rust's growable list: Python's list, with every item of one type. Its items sit side by side in one block on the heap, and when the block is full it asks for a bigger one.

Where it's taught: week zero, tuples, arrays and vectors

working directory

The folder a process counts as "here". A relative path like data/kettle_creek.db is looked up from it, not from where the source file is, which is why you run cargo run from the project folder.

Where it's taught: week zero, your program is a process
